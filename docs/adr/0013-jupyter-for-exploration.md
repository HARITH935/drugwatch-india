# ADR 0013 — Jupyter + matplotlib for exploration, in an `analytics/` project

- **Status:** accepted
- **Date:** 2026-11-19
- **Phase:** 6 (Analytics), step 1
- **Decided by:** Harith

## Context

Plan §9 Phase 6 step 1 asks for a "Pandas exploration notebook: distributions, top manufacturers,
failure categories, seasonality, data gaps". The locked stack (§6) lists **Pandas** under
Analytics, but nothing to run a notebook in and nothing to draw a chart with.

The work is genuinely exploratory: look at a distribution, notice something, ask the next
question. That is what a notebook is for, and it is also what makes a notebook dangerous here -
its saved output is the data itself, and ADR 0003 forbids real CDSCO rows in this repo.

## Decision

1. **Jupyter (jupyterlab + nbconvert + ipykernel) and matplotlib** are added, for exploration only.
2. Exploration lives in a new **`analytics/`** uv project, beside the other Python folders.
3. The notebook reads the **gold layer only** (CLAUDE.md §5), through a small helper module -
   `drugwatch_analytics.gold` - so the SQL is testable and the notebook stays thin.
4. **Notebooks are committed with their outputs cleared**, enforced by a repo check that fails if
   any `.ipynb` carries output. Findings worth keeping are written as **aggregates** into
   `docs/analytics-findings.md`, never as rows.
5. No seaborn, plotly or any other plotting library: matplotlib alone, so there is one way to draw
   a chart and one dependency to justify.

## Why

- **A notebook is the honest tool for this step and the wrong tool for every other.** Nothing
  scheduled or reused may live in one: Phase 5 runs the pipeline, dbt holds the SQL, and the ML
  code in Phase 7 belongs in modules. The notebook exists to decide what the dashboards should
  show, and the module it imports is where anything reusable goes.
- **Cleared outputs are a data-protection measure, not tidiness.** A notebook with outputs is a
  file full of batch numbers and manufacturer names - exactly what ADR 0003 keeps out of git. A
  check that fails the commit is the only version of this rule that survives a tired evening.
- **Gold only, like Superset and the model.** Reading silver directly would be faster to write and
  would quietly create a second definition of every figure. The dashboards read gold, so the
  exploration that designs them must read the same thing.
- **matplotlib is enough.** The charts here exist to be looked at once, by one person, while
  deciding what Superset should render. Superset draws the public ones.

## Consequences

- `analytics/` is a new CI matrix entry and a new line in `CLAUDE.md` §9/§10.
- The repo-check script gains a notebook-output check, so CI catches a notebook committed with its
  outputs.
- Charts in the notebook are not reproducible from the repo alone (the data is not committed): they
  are regenerated by running the notebook against a loaded warehouse. The *findings* are durable
  because they are written to `docs/analytics-findings.md` as aggregates.
- Jupyter is a sizeable dependency tree (~200 MB) for one project folder. Accepted: it is the
  standard tool, and `uv` keeps it out of every other project's virtualenv.

## Alternatives rejected

| Option | Why not |
|---|---|
| A plain `.py` script with printed tables | Loses the "look, then ask the next question" loop that is the entire point of step 1 |
| `marimo` / other notebook formats | A reviewable plain-text notebook is appealing, but Jupyter is what an interviewer, a reader and every tutorial expect |
| Commit notebooks with outputs | Would put real CDSCO rows in git, against ADR 0003 |
| Explore against silver Parquet | Two definitions of every number; the dashboards read gold |
| seaborn / plotly as well | A second plotting library to justify for charts nobody but us sees |
